# agentbus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cross-machine messaging between Claude Code sessions, built into the CLIProxyAPI fork, with self-setup and idle wake-up.

**Architecture:** New package `internal/agentbus` (registry, inboxes, persistence, HTTP handlers, request injection, served setup script). `internal/api` mounts the endpoints under `/v1/agentbus` and wraps `POST /v1/messages` with an injection middleware. Client side is a `sh` waiter installed by a served setup script as `SessionStart` and `Stop` hooks with `asyncRewake`.

**Tech Stack:** Go 1.26 (gin, gjson/sjson already in go.mod), POSIX sh + curl + python3 on clients.

**Spec:** `docs/superpowers/specs/2026-10-02-agentbus-design.md`

## Global Constraints

- All endpoints under `/v1/agentbus`, behind the existing `/v1` client-key middleware.
- Tailnet only; no external publishing.
- State file `agentbus-state.json` in `util.WritablePath()`, else next to the config file; atomic writes.
- Injection must never break a request: on any error forward the original body.
- No timeouts on upstream connections (AGENTS.md); the `/wait` long-poll timer is a server-side wait, not an upstream timeout.
- No em or en dashes in code, comments, docs or commit messages. No AI attribution in commits.
- Build and test only inside `golang:1.26-bookworm` on cakebox (`/tmp/cpa-src`); gofmt the files touched.
- Deploy through a canary on a spare port, then swap production (Claude Code itself runs through this proxy).

## Review Focus

1. A message claimed for injection into a request that then fails must return to the front of the inbox (no loss). Test in Task 3.
2. Two waiters for one session (SessionStart and Stop overlapping): the newer one wins, the older returns 409 and exits silently, no double delivery. Test in Task 2.
3. Subagent requests (agent-id header) never receive injections, and do not consume messages. Test in Task 3.
4. String-form `content` on the last user message is converted to a block array before appending; a request whose last message is not `user` is left unchanged. Test in Task 3.
5. Setup script merge is idempotent and preserves unrelated hooks (peon-ping, ponytail-sync). Test in Task 4.

### Task 1: Store (registry, addresses, names, inbox, persistence)

**Files:** Create `internal/agentbus/store.go`, `internal/agentbus/store_test.go`

**Interfaces (produced):**
- `type Store struct` with `NewStore(statePath string, now func() time.Time) *Store`, `Load() error`, `Save() error` (writes only when dirty).
- `(s *Store) Touch(sessionID string)` (a main or subagent request seen), `BeginRequest(id)`, `EndRequest(id)`.
- `(s *Store) Hello(id, machine, cwd, name string)` (sets fields, marks waiter seen, applies name if free).
- `(s *Store) SetName(id, name string) error` (`ErrNameTaken`, empty clears).
- `(s *Store) Resolve(target string) (sessionID string, ok bool)` by name or address.
- `(s *Store) Address(id string) string`.
- `(s *Store) Send(fromID, to, body, replyTo string) (Message, error)` (`ErrUnknownTarget`, `ErrBodyTooLarge` > 16 KiB, `ErrUnknownSender`).
- `(s *Store) Claim(id string) []Message`, `(s *Store) Return(id string, msgs []Message)` (front of inbox).
- `(s *Store) Peers() []Peer` with `Peer{Address, Name, Machine, Cwd, Status, LastSeen}`; status busy/idle/away/offline per spec; offline older than 24h dropped.
- `(s *Store) Notify(id string) <-chan struct{}` for waiters; `Send` closes/replaces the channel.
- Expiry: messages older than 7 days dropped on Claim/Save.

**Tests:** address formatting (`unknown` machine before hello, sanitizing, 6-char id); name claim, uniqueness, clear, resolve by name and address; send to unknown target 404 error; body size limit; claim empties inbox, return restores order at front; status transitions with a fake clock; offline after 24h dropped; persistence round trip; expiry.

### Task 3: Request injection middleware

**Files:** Create `internal/agentbus/inject.go`, `internal/agentbus/inject_test.go`

**Interfaces:** `func (s *Store) InjectMiddleware(baseURLHint string) gin.HandlerFunc`. Reads `X-Claude-Code-Session-Id`, `X-Claude-Code-Agent-Id`. Always `Touch`. Main-thread only: `BeginRequest`/`EndRequest` around `c.Next()`; builds note (first request of the session, or peer list changed since last note, plus setup line once when no waiter within 2 minutes of first request) and claimed messages; appends a text block to the last `user` message via sjson; replaces `c.Request.Body` and `ContentLength`; after `c.Next()`, if `c.Writer.Status() >= 400`, `Return` the claimed messages. `func noteText(...) string` per the spec's template, including the session id in the send command.

**Tests:** string content converted to blocks with the note appended; block content gets one extra text block; last message not user: body unchanged and messages not claimed; subagent request: no injection, inbox untouched; failing downstream (handler writes 500): messages returned to inbox front; second request without new peers or messages: body unchanged; setup line appears once after the 2-minute window with no waiter.

- [ ] Write tests, fail, implement, pass, commit.

### Task 4: Setup script and waiter

**Files:** Create `internal/agentbus/setup.go` (embedded templates), `internal/agentbus/setup_test.go`

**Behavior:** `GET /setup` returns an `sh` script (text/plain) with the base URL taken from the request Host. The script writes `~/.claude/hooks/agentbus/wait.sh`, merges `SessionStart` and `Stop` entries `{type: command, command: "<home>/.claude/hooks/agentbus/wait.sh", asyncRewake: true}` into `~/.claude/settings.json` with python (idempotent: skip if an entry with that command exists), then posts `/hello` using `CLAUDE_SESSION_ID` when known (otherwise the waiter's first `/hello` covers it). `wait.sh` reads stdin JSON with python (`session_id`, `cwd`, `transcript_path`), extracts the latest `customTitle` from the transcript, posts `/hello`, then loops `curl -s -o body -w '%{http_code}' --max-time 70 .../wait?...`: 200 prints messages (sender, id, body, reply hint) to stderr and exits 2; 204 loops; 409 exits 0; errors back off (5, 15, 30, 60 s) then exit 0 after ~5 minutes. Requires `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` (present via settings env); exits 0 if missing.

**Tests:** in Go, render the script and check it contains the hook command and base URL; run the script with `sh` against a temp HOME containing a settings.json with an existing SessionStart hook (python3 available in the build image? if not, install `python3` in the test step container) twice, and assert both hooks present once and the original hook kept; run `wait.sh` against an httptest server returning 200 with one message and assert exit code 2 and stderr text; 409 gives exit 0.

- [ ] Write tests, fail, implement, pass, commit.
